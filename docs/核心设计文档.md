# 长夜誓约 / Oath of Long Night — 核心设计文档 v0.2

> 状态：设计阶段
> 目标平台：Windows（GOG + Steam），中文 + 英文
> 引擎：Godot 4.3+（GL Compatibility）
> 参考：刀塔传奇（结构与节奏）× 无随机抽卡

**v0.2 变更**：确定同场双角色、确定城镇为单屏据点「灯下」、明确不做手柄支持。

---

## 1. 定位一句话

**在一场吞没世界的长夜里，你与六个互不信任的誓约者签订有代价的契约，借他们的力量走到黎明。**

- 类型：2D 等距视角动作 RPG
- 单人体验，无多人，无内购，无手柄
- 一次性买断
- 借鉴：刀塔传奇的关卡节奏、角色搭配、Boss 战设计
- 拒绝：抽卡、每日签到、体力、限时活动、任何随机付费

## 2. 设计三原则

**原则一：驱动力来自"代价"，不是"运气"。**
每一个强力角色都必须通过某种牺牲获得——献祭记忆、献祭寿命、献祭某样珍贵的东西。玩家清楚地知道自己付出了什么，因此角色的分量感远超抽卡得到的。

**原则二：所有系统都必须能被"看懂"。**
没有隐藏的暴击率、没有看不见的伤害加成、没有洗练出重复词条的烦躁。Build 的乐趣来自组合的发现，不来自随机的赌博。

**原则三：可通关，不逼氪，不逼肝。**
主线 15–20 小时可完结，全收集 40 小时左右。任何角色都不需要花钱、不需要连续签到才能获得。

---

## 3. 核心循环

```
探索长夜 → 誓战（实时战斗） → 积累（誓印/装备/词条） → 灯下（誓约签订与养成） → 解锁更深的夜
```

**三个关键指标目标**
- 单次普通战斗：60–120 秒
- 单个Boss 战：3–5 分钟（分段，有机制转换）
- 一章（8–10 关）：2–3 小时

## 4. 誓约系统（替代抽卡的核心机制）

### 4.1 誓约的本质
誓约是"以代价换取力量"的契约。每个角色有自己的**誓约条件**，玩家在特定剧情节点完成条件后，与其签订不可逆的契约。

### 4.2 誓约条件类型（示例）

| 角色 | 誓约条件 | 代价 |
|---|---|---|
| 灰烬骑士 | 在第一章末存活并独自击败 Boss | 失去全部治疗能力（永久） |
| 双生剑姬 | 收集 5 个特定的记忆碎片 | 遗忘她妹妹的存在 |
| 老灯守 | 通关第三章，不使用任何治疗道具 | 每场战斗缩短 2 分钟 |
| 静默修士 | 达成 5 个隐藏条件 | 战斗全程无 UI 显示数值 |
| 血契狼 | 累计战败 20 次 | 生命上限永久降低 |
| 无名誓约者 | 收集 12 个碎片（分散在全部地图） | 结局不同 |

### 4.3 设计意图
- **代价是永久且可感知的**——不是隐藏 debuff 数字，而是玩家能亲眼看到的限制
- **代价制造玩法而非惩罚**：失去治疗 → 必须靠闪避和护盾；无 UI → 玩家被迫记住数值
- **誓约是可炫耀的**：完成所有誓约 = 通向真结局，这是买断制玩家愿意反复玩的目标

## 5. 战斗系统（已定：同场双角色）

### 5.1 同场配置
- **主角 + 1 名誓约者 = 2 人同时在场**
- 战斗外可自由更换誓约者，阵容搭配是玩家的核心决策
- 战斗中按 `空格` 瞬切，双方各获 0.5 秒无敌与演出停顿
- 誓约者不是"备用血包"，他有自己的定位（输出 / 坦克 / 辅助 / 控制）

### 5.2 誓约者 AI：三档指令

玩家只做选择，不写复杂 AI，却仍有战术深度：

| 指令 | 行为 |
|---|---|
| **跟随**（默认） | 贴近玩家，攻击玩家附近敌人，优先解控 |
| **压制** | 主动追击，主动放技能，不顾自身血量 |
| **守护** | 留在玩家身边，拦截朝玩家来的投射物与突进敌人 |

AI 随誓约印记解锁新行为（嘲讽、治疗、位移、控制），让养成有战术回报而不只是数值。

### 5.3 誓约共鸣（替代"凑阵容"的动力来源）

这是本作对刀塔传奇最重要的改造。

**条件**：两名角色在 **2.5 秒内对同一目标造成伤害**
**结果**：触发双人合击，有专属演出（约 1.2 秒），强度与角色投入相关

```
主角命中   ┐
           ├── 同一目标 2.5 秒内被两人命中 → 誓约共鸣 → 合击演出
誓约者命中 ┘
```

**6 组专属合击**（每组角色组合各有其演出与效果）：

| 组合 | 合击名 | 效果 |
|---|---|---|
| 灰烬骑士 + 双生剑姬 | 余烬之刃 | 直线斩击，附带灼烧 |
| 老灯守 + 静默修士 | 长明 | 生成高伤持续光域 |
| 血契狼 + 无名誓约者 | 月下狂犬 | 全屏撕咬，回复双方生命 |
| 主角 + 任一誓约者 | 誓约回响 | 通用保底合击，保证任何组合都有反馈 |

**设计意图**：玩家追求的不是"收集强度"，而是"收集组合"。这是无抽卡设计里唯一能长期驱动玩家去解锁新角色的机制。

### 5.4 操作（无手柄）

| 操作 | 按键 |
|---|---|
| 移动 | `W A S D` |
| 普通攻击 | 鼠标左键 |
| 技能 | `Q` `E` `R` |
| 闪避 | `Shift`（短无敌帧，核心生存技） |
| 切换角色 | `空格` |
| 切换 AI 指令 | `F` |
| 视角缩放 | 滚轮 |
| 暂停 / 地图 | `Tab` / `Esc` |

**明确不做手柄**：降低 UI 与测试成本，也符合"鼠标键盘为默认"的 GOG 用户画像。

### 5.5 战斗特点（区别于刀塔传奇）
1. **闪避有重量感**：短无敌帧 + 技能可取消后摇，鼓励主动进攻而非站桩
2. **敌人有明确预警**：Boss 蓄力动作清晰可辨，可被躲，不靠数值硬拼
3. **共鸣系统**：两人协同才有高光时刻，把"配合"变成爽点

## 6. 城镇：灯下（单屏据点）

### 6.1 设计取舍：不做可行走城镇

可行走城镇意味着第二套地图管线——建筑外观、门内场景、NPC 动画、碰撞、传送逻辑。对个人开发是数倍成本，且对玩法体验的增量很有限。

**方案**：单屏据点 + 点击前往。类似《哈迪斯》的宅邸、《暗黑地牢》的村庄。

### 6.2 呈现方式
- 一张高细节手绘背景：提灯、雨或雪、静谧的废墟
- 前景剪影，镜头有轻微视差
- 玩家点击场景中的物件或角色执行功能
- **不做时间消耗、不做商店售卖**（避免变成刷资源商店）

### 6.3 灯下的功能点

| 物件 | 功能 |
|---|---|
| **誓约碑** | 签订 / 查看誓约，解锁新角色（有独立演出） |
| **铸铁台** | 装备打造与洗练（洗练只改数值，不换词条） |
| **誓约之厅** | 角色列表、誓约印记加点 |
| **长夜图** | 世界地图，选择章节 |
| **记忆镜** | 图鉴、剧情回看、结局统计 |
| **灯** | 存档点 + 休息（状态全满） |

### 6.4 灯下也是叙事场所

角色会在灯下对话，誓约签订有独立过场演出。这让玩家的"挂机点"变成**故事发生地**，而不是纯菜单界面——同时也是誓约条件达成的检查点。

## 7. 成长维度

- **角色等级**：基础属性
- **誓约印记**：每角色 3 条誓约线，选择不同分支（无优劣，只有风格差异）
- **装备词条**：6 个槽位，词条池**完全公开**，可洗练（改数值不换词条）
- **共鸣熟练度**：合击使用次数解锁合击变体（不消耗资源）

明确不做：装备掉落随机词条、宝石镶嵌、洗练出重复词条。

| 内容 | 数量 | 备注 |
|---|---|---|

| 合击演出 | 6 组 | 每组含基础版 + 熟练度变体 |
| 结局 | 3 个 | 需完成对应誓约才能解锁 |

## 9. 美术方向（2D 等距）

- **视角**：45° 俯视等距（2:1 菱形地块），参考《暗黑破坏神 2》+《火炬之光》
- **风格**：手绘厚涂，低饱和暗色调 + 誓约特效的高对比光
- **光照**：以角色为中心的动态光圈，长夜主题的黑暗需要光来"划出"可读区域
- **灯下**：单张高细节背景 + 视差层，不做行走

### 9.1 资源量估算（这是产能的关键数字）

| 项目 | 帧数 | 备注 |
|---|---|---|
| 角色 | 约 320 帧/角色 | 8 方向 × 待机/走/攻击/受击 |
| 敌人 | 约 150 帧/类型 | 8 方向 × 4 状态 |
| 地块 | 40 种 + 100 件装饰 | |
| 灯下背景 | 3–4 层 | 静态图，量小 |
| **总计** | **约 6000+ 帧** | |

**建议**：角色立绘与关键动画外包，自己做整合、特效、敌人。灯下背景成本极低但观感收益极高，优先做好。

## 10. GOG 上架要点

- **定价**：建议 ¥68 / $9.99 档位
- **DRM**：GOG 要求 DRM-free，Godot 导出天然满足
- **语言**：中文、英文（英文需母语润色）
- **成就**：约 40 个
- **云存档**：GOG Galaxy 云存档，可作为卖点
- **退款窗口**：GOG 标准 14 天无理由退款，**首日体验必须完美**
- **Demo**：建议上架前 1–2 个月放出
- **商店页素材**：至少 5 张截图 + 1 支 60–90 秒预告片

### 10.1 GOG vs Steam
建议**同时上 Steam + GOG**。GOG 用户偏好 DRM-free 与无内购的精品，Steam 有更大的曝光与愿望单机制。两家后台上架成本低（同一份构建）。

**但首发时机要错开 2–4 周**，便于收集 Steam 早期评价——Steam 的评价数与评分直接影响曝光，而 GOG 的销量很大程度上依赖 Steam 口碑。

## 11. 开发路线（12 个月）

| 阶段 | 时间 | 目标 | 验收标准 |
|---|---|---|---|
| P0 技术验证 | 1–2 月 | 双角色移动、普攻、闪避、共鸣触发的手感 | 内部试玩不难受，2 人配合有乐趣 |
| P1 垂直切片 | 3–5 月 | 1 章完整流程：2 角色 + 1 Boss + **灯下据点** | 20 分钟完整体验，可对外试玩 |
| P2 内容量产 | 6–9 月 | 5 章全部内容、8 角色、6 组合击 | 主线可通关 |
| P3 打磨与优化 | 10–11 月 | 美术统一、数值平衡、成就、UI | 无 Bug、无卡顿 |
| P4 上架准备 | 12 月 | 英文本地化、商店页、预告片、试玩版 | GOG 审核通过 |

**风险提示**：P2 是最大的坑。内容量产阶段最容易崩。建议在 P1 结束时评估一次，如果进度落后，优先砍章节数（5 章 → 3 章），**绝不砍 Boss 质量与合击演出**——那是玩家记住游戏的部分。

## 12. 决策记录

| 编号 | 决策 | 内容 | 理由 |
|---|---|---|---|
| D-001 | 画面 | 2D 俯视等距 | 成本可控，2D 产能最高 |
| D-002 | 收集 | 无抽卡，改为誓约献祭 | GOG 玩家反感随机开箱；代价驱动比运气驱动更有分量 |
| D-003 | 引擎 | Godot 4.3+ GL Compatibility | 2D 主场、导出体积小、GOG 审核快 |
| D-004 | 战斗 | 同场双角色（主角 + 1 誓约者） | 比单角色切换更有策略与观赏性，且与"誓约共鸣"设计自洽 |
| D-005 | 城镇 | 单屏据点「灯下」，不做可行走 | 个人开发产能有限，单屏能把美术质量做高 |
| D-006 | 操作 | 不做手柄支持 | 降低 UI 与测试成本 |
| D-007 | 平台 | Steam + GOG 双平台，首发错开 2–4 周 | GOG 销量依赖 Steam 口碑 |
